## 2. 已完成的工作（按平台）

### 2.1 QEMU 侧（同事 xjysiiau 主导，我本机完整复现）

- **pointer_masking 三个修复实验**已发到 issue（08-22）：测试侧改 PR_TAGGED_ADDR_ENABLE → SIGSEGV；内核侧只记 PMLEN 不改 envcfg → 无效；结论是**测试期望与内核语义矛盾**，需重写测试。仓库：<https://github.com/xjysiiau/kernelci-riscv>
- **我本机复现的闭环**（QEMU 10.2.1 + 内核 v7.2-rc7 + openKylin 镜像）：
  boot ✅ / 配置漂移检查 ✅ / cpuinfo ✅ / vector ✅（VLEN=128）/ **全量 kselftest 9 pass / 0 skip / 1 xfail** ✅

### 2.2 真机 #1：Lichee Pi 3A（SpacemiT K1）

| 项 | 结果 |
|---|---|
| cpuinfo ISA | **PASS**（`rv64imafdcv_...`，含 Vector） |
| 向量功能 | **PASS**，**VLEN = 256 bits**（QEMU 为 128） |
| 向量性能（419 万元素） | **36.058 ms**（QEMU 380.263 ms → 真机快 **≈10.5×**） |
| 启动链证据 | U-Boot → OpenSBI → 内核（`earlycon=sbi`），eMMC 引导 |
| 回归趋势 + CI | ✅ 自托管 runner 自动跑并回填 `results/trend.md` |
| 已知边界（如实） | **无 H 扩展**（真机 KVM 不可行）、**无 ZPM**、板载内核 6.1.15 → 全量 kselftest 待升级 |

### 2.3 真机 #2：SiFive HiFive Premier P550（本轮新增）

仓库 `kernelci-riscv-p550`：**21 提交 / 192 文件 / 13 次真机运行**，最新一次 **OVERALL: PASS**。

| 项 | 结果 |
|---|---|
| 扩展画像（实测） | **有 H、无 V、无 ZPM、mmu = sv48** —— 与 li3a（有 V、无 H、sv39）**完全互补** |
| **真机 Hypervisor（KVM）** | ✅ **PASS**：`kvm.ko` 加载后客户机在真 H 扩展上执行并产生预期 MMIO 退出。dmesg 证据：`hypervisor extension available`、`Sv48x4 G-stage page table format`、`VMID 0 bits available` |
| riscv kselftest 子集 | **3 pass / 0 fail / 4 skip**；缺 V/ZPM 的用例按平台能力记 SKIP 而非 FAIL |
| `riscv_hwprobe(2)` 权威探针 | ✅ 与 `/proc/cpuinfo` 交叉验证 **17 项全部一致** |
| 跨平台扩展矩阵 | P550 / li3a / QEMU 三方对照（`docs/extension-matrix.md`） |
| CI 真机自动化 | 自托管 runner：push 触发已按需改为**手动触发**（避免占用他人板子） |
| **test profile 实体化** | `profile/riscv-extensions.json` + `scripts/check-profile.py`：把"期望值"变成**可执行断言**，每次运行自动判漂移 |
| **KCIDB 结果对接** | `scripts/kcidb-emit.py`：真机结果 → KernelCI 数据格式，**官方 kcidb-io v5.3 schema 校验通过** |

**本轮产出的上游可行动发现（5 条，`integration/kernelci/upstream-findings.md`）**：

1. `riscv/sigreturn` **没有 V 能力门控** → 无 V 真机上 SIGILL 而非 SKIP（源码级确认；已做到**无硬件复现**）
2. 两个 nolibc 向量测试用 `exit(-1)`＝255 表示"平台不支持"，而 kselftest 约定 SKIP＝4
3. 厂商内核"编译进的能力 ≠ 硬件有的能力"（ESWIN 6.6.92 编了 V/SVPBMT/ZICBOM 但硬件没有）
4. 厂商内核 KVM ISA 位图与上游枚举对不上（已用身份字段自检排除"读错"）
5. 厂商内核对未定义 hwprobe key 返回 0 而非上游约定的 -1

> 其中 1、2 是**源码级确认 + 真机与 QEMU 用户态双平台复现**，可直接上报；4、5 为单样本观测，待求证。

## 3. 与上游/另一位贡献者的分工（经核查，重要）

**事实核查（直接读 kernelci/kernelci-pipeline 的配置）**：

1. `config/platforms.yaml` 里**已有** `eic7700-hifive-premier-p550` 平台定义；
2. `config/scheduler.yaml` 里 `baseline-riscv-collabora` 这一个 job **同时覆盖两台真机**：

```yaml
- job: baseline-riscv-collabora
  platforms:
    - spacemit-k1-bananapi-f3        # SpacemiT K1 —— 与我们的 Lichee Pi 3A 同 SoC
    - eic7700-hifive-premier-p550    # SiFive HiFive Premier P550
```

→ **真机接入（P550 + K1）上游已具备**（RISE RP012 / Collabora 的 LAVA lab）。
因此"我们有真机"**不是**差异点，汇报时不能这么讲。

3. 另一位贡献者 [Hao-Chen2337](https://github.com/Hao-Chen2337) 的 PR
   [kernelci/kernelci-pipeline#1599](https://github.com/kernelci/kernelci-pipeline/pull/1599)
   新增了 `kselftest-riscv` 与 `kselftest-kvm` 两个 job，但**只挂在 `qemu-riscv64` platform 上**
   —— 真机上一个都没有。

**结论：真正的缺口是"真机上的扩展测试"，不是"真机本身"。**

| 维度 | 上游已有 | 缺口（＝我们的空间） |
|---|---|---|
| P550 / K1 真机接入 | ✅ platform + `baseline` job | — |
| 真机上的扩展测试（V/H/漂移） | ❌ 真机只有 baseline | ✅ **我们的 test profile** |
| `kselftest-riscv` / `kselftest-kvm` | 仅 QEMU（#1599） | ✅ **真机上的同一套**（P550 有真 H） |
| 真机 vs QEMU 对照数据 | ❌ | ✅ 我们能产出 |
| 配置漂移检测 | 仅"同 commit 两次构建"（QEMU 侧 5412 项 0 漂移） | ✅ **内核配置 vs 硬件能力**（已抓到真实漂移） |
| 上游测试缺陷发现 | ❌ | ✅ 5 条（其中 2 条可无硬件复现） |
| 容器化流水线 / Phase 3 PR | ✅（#1599） | 不重复做 |

**对"板子是否必需"的结论**：板子**不是交付物，只是开发工具**。
若我们的 profile 被上游接受，它会跑在 Collabora lab 已有的 P550 / BPI-F3 上；
我们自己的板子只用于**快速产出对照数据**，**离线不阻塞任何交付**。
